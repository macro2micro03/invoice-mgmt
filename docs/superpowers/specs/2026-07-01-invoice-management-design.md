# AI 기반 건설자재 입고관리 시스템 — 설계 문서 (MVP)

## 배경 및 목표

현장 품질 담당자(2~3명)가 거래명세서/송장/납품서를 모바일로 촬영하면, AI(OCR)가 정보를 추출하고 사용자가 검토/수정한 뒤 저장하면 DB, 사진, 엑셀(Master.xlsx), 주요자재 입고서류(PDF)를 자동으로 생성하는 시스템.

- **사용자 규모**: 현장 품질직군 2~3명, 같은 Wi-Fi(LAN)에서 사용
- **로그인**: 없음 (신뢰 가능한 소규모 인원이므로 MVP에서 생략)
- **MVP 범위**: 촬영/갤러리 선택 → OCR 인식 → 수정 화면 → DB 저장 → 엑셀 자동작성 → 주요자재 PDF 자동생성 → 검색/수정
- **MVP 제외 (향후 확장)**: 발주서 대조, 입고검사 체크리스트, 통계 대시보드, 오프라인 저장, 사용자 로그인, 전자결재

## 아키텍처

```
[모바일 브라우저 - PWA]  --LAN(Wi-Fi)-->  [FastAPI 백엔드 - 사용자 PC/홈서버]
                                                |-- SQLite DB
                                                |-- 로컬 파일 저장 (사진 원본 / Master.xlsx / PDF)
                                                |-- Upstage Document AI API 호출 (인터넷)
```

- **프론트엔드**: React + Vite 기반 PWA. `vite-plugin-pwa`로 설치 가능하게 구성. 카메라 입력은 `<input type="file" accept="image/*" capture="environment">` 사용.
- **백엔드**: FastAPI, `uvicorn`으로 사용자 PC/홈서버에서 직접 구동. 방화벽에서 LAN 접속 포트 허용.
- **DB**: SQLite 단일 파일 (`invoices.db`). 향후 필요 시 PostgreSQL로 이전 가능하도록 SQLAlchemy ORM 사용.
- **OCR**: Upstage Document AI REST API. API 키는 백엔드에만 보관 (프론트에 노출 안 함).
- **네트워크 모델**: 로그인 없음 + LAN 내부 접속만 허용(포트포워딩 없음) → 신뢰된 인원만 접속 가능한 전제.

## 데이터 흐름

1. **촬영/선택**: 사용자가 PWA에서 사진 촬영 또는 갤러리에서 선택.
2. **OCR 요청**: 이미지를 백엔드 `POST /ocr`로 전송.
3. **OCR 처리**: 백엔드가 Upstage Document AI 호출 → 응답을 표준 필드로 매핑:
   - 자재종류, 거래처, 납품일, 차량번호, 송장번호, 품명, 규격, 단위, 수량, 중량, 비고
   - 인식 실패/저신뢰 필드는 빈 값으로 반환 (저장을 막지 않음)
   - OCR API 타임아웃/실패 시에도 빈 폼을 반환하여 수동 입력 가능
4. **수정 화면**: 프론트가 추출된 값으로 폼을 미리 채움. 사용자가 확인/수정.
5. **저장**: `POST /invoices`
   - DB에 먼저 저장 (핵심 데이터 손실 방지 원칙 — 이후 단계 실패해도 데이터는 보존됨)
   - 원본 사진을 로컬 디스크에 저장, 경로를 DB에 기록
   - Master.xlsx에 자재종류별 시트로 행 append (시트 없으면 생성)
   - 자재종류가 "주요자재"(철근, 철골, 레미콘, 시멘트 등)면 PDF 입고서류 자동 생성
   - 엑셀/PDF 생성 단계가 실패해도 에러만 로깅하고 사용자에게는 저장 완료로 응답 (재시도 가능한 별도 배치/재생성 기능은 향후 확장으로 남김)
6. **검색/조회**: `GET /invoices?거래처=&자재종류=&날짜=&송장번호=` 등 조건 조회. 상세 화면에서 원본 사진 확인 및 수정 가능.

## 데이터 모델

SQLite 테이블 `invoices` (단일 테이블, MVP 범위에 맞게 최소화):

| 필드 | 타입 | 설명 |
|---|---|---|
| id | INTEGER PK | 자동 증가 |
| material_type | TEXT | 자재종류 (철근/철골/레미콘/시멘트/골재/거푸집/단열재/배관/전기자재/마감재 등) |
| vendor | TEXT | 거래처 |
| delivery_date | DATE | 납품일 |
| vehicle_no | TEXT | 차량번호 |
| invoice_no | TEXT | 송장번호 |
| item_name | TEXT | 품명 |
| spec | TEXT | 규격 |
| unit | TEXT | 단위 |
| quantity | REAL | 수량 |
| weight | REAL | 중량 |
| note | TEXT | 비고 |
| photo_path | TEXT | 원본 사진 저장 경로 |
| created_at | DATETIME | 생성 시각 |
| updated_at | DATETIME | 수정 시각 |

## 에러 처리 원칙

- **저장 우선순위**: DB 저장 성공 = 그 건은 "저장 완료" 취급. 이후 파생 산출물(사진 파일, 엑셀, PDF) 생성 실패는 사용자 작업을 막지 않고 서버 로그로만 기록.
- **OCR 실패**: 네트워크 오류/타임아웃 시 빈 폼 반환, 수동 입력으로 전환. 저신뢰 필드는 빈 값 처리(잘못된 값을 억지로 채우지 않음).
- **엑셀/PDF 생성 실패**: 에러 로깅. MVP에서는 자동 재시도 없음 (재생성 기능은 확장 범위).

## 기술 스택

- **Frontend**: React, Vite, vite-plugin-pwa
- **Backend**: FastAPI, SQLAlchemy, openpyxl (엑셀), reportlab (PDF)
- **OCR**: Upstage Document AI REST API
- **DB**: SQLite
- **배포**: 사용자 PC/홈서버에서 `uvicorn` 직접 구동, LAN 방화벽 포트 허용, 정적 프론트 빌드는 FastAPI에서 함께 서빙

## 테스트 전략

- **백엔드 (pytest)**:
  - OCR 응답 → 표준 필드 매핑 로직 단위 테스트 (정상/부분 인식/실패 케이스)
  - DB CRUD 테스트 (저장, 조회, 수정)
  - 엑셀 append 로직 테스트 (신규 시트 생성 포함)
  - PDF 생성 로직 테스트 (주요자재 여부 분기 포함)
- **프론트엔드**: 실제 폰으로 LAN 접속하여 촬영 → OCR → 수정 → 저장 → 검색 전체 플로우 수동 테스트 (카메라/오프라인 캐싱 등 브라우저 환경 의존 기능이라 자동화 테스트보다 수동 검증 우선)

## 향후 확장 (MVP 이후, 별도 spec으로 진행)

- 발주서 대조
- 입고검사 체크리스트
- 통계 대시보드
- 오프라인 저장 (PWA 완전 오프라인 지원)
- 사용자 로그인 / 권한 관리
- 전자결재
