# 누적 수불부 관리 — 설계 문서

## 배경

`2026-08-10-material-ledger-design.md`에서 구현한 수불부 생성 기능은 매번 완전히 새 파일을 만들고, 그때 검색에서 선택한 송장만 채운다 — 이전에 생성했던 수불부의 내용을 기억하지 않는다. 실제 현장에서는 수불부를 "계속 쌓이는 하나의 장부"로 관리하고 싶어 한다: 새 송장이 등록될 때마다 기존 수불부 아래에 이어붙여지고, 예전 항목의 값을 고치면 다음 생성 시 반영되고, 특정 건을 장부에서 빼고 싶을 때 뺄 수 있어야 한다.

## 핵심 설계 결정: 파일을 저장하지 않고 매번 재생성한다

실제 엑셀 파일을 서버에 저장해두고 열어서 이어붙이는 방식은 파일 손상 위험이 있고, 수정/제외 요구사항을 처리하기 어렵다(바이너리 파일 안의 특정 행을 찾아 고치거나 지워야 함). 대신:

- `Invoice`에 **"수불부 포함 여부" 플래그**만 저장한다.
- 다운로드할 때마다 **플래그가 켜진 모든 송장**을 반입일 오름차순으로 정렬해 처음부터(7행부터) 다시 채운 새 파일을 만든다.

이렇게 하면:
- 이미 포함된 송장의 값(규격/반입일/반입량)을 수정 화면에서 고치면, 다음 수불부 생성 시 DB에서 다시 읽어오므로 **자동 반영**된다.
- 특정 건을 수불부에서 빼고 싶으면 플래그만 끄면 되고, 송장 기록 자체는 유지된다.
- 연번은 매번 정렬된 목록의 순서로 새로 매기므로, 중간에 제외된 게 있어도 항상 1부터 빈 번호 없이 채워진다.

## 데이터 모델 변경

`backend/app/models.py`의 `Invoice`에 컬럼 추가:

```python
included_in_ledger = Column(Boolean, nullable=False, default=False, server_default="0")
```

기존 배포 DB(SQLite 로컬 + Render의 Postgres)에 마이그레이션이 필요하다 — 이 프로젝트는 별도 마이그레이션 도구(Alembic 등)를 쓰지 않고 `Base.metadata.create_all`로 스키마를 관리하므로, 기존 테이블에 컬럼을 추가하려면 앱 시작 시 컬럼 존재 여부를 확인하고 없으면 `ALTER TABLE`을 실행하는 간단한 마이그레이션 코드를 `database.py`에 추가한다(SQLite와 Postgres 양쪽에서 동작하는 문법 사용).

## 백엔드 동작 변경

### `/reports/material-ledger` (기존 엔드포인트 수정)

기존 흐름(선택한 `invoice_ids`로 커플러/비철근 제외 → 반입일 정렬 → 채우기)에서 바뀌는 부분:

1. 선택한 `invoice_ids` 중 커플러/비철근은 기존과 동일하게 제외
2. 남은 것 중 `included_in_ledger == True`인 건은 **"이미 포함됨"으로 별도 집계**해서 건너뛰고, 개수를 경고 메시지에 포함
3. 나머지(신규)는 `included_in_ledger = True`로 표시하고 DB에 커밋
4. **파일을 채울 때는 방금 선택한 것만이 아니라, `included_in_ledger == True`인 전체 송장**(철근 + 커플러 아님, 이 조건은 플래그를 켤 때 이미 보장됨)을 반입일 순으로 조회해서 사용
5. 채울 대상이 하나도 없으면(신규도 없고 기존 포함 목록도 비어있으면) 400

경고 메시지 예시: "이미 수불부에 포함된 2건은 건너뛰었습니다" (제외됐던 커플러 경고와 별개 문구로 구분)

### `GET /reports/material-ledger/entries` (신규 엔드포인트)

현재 `included_in_ledger == True`인 송장 목록을 반입일 순으로 반환한다 (연번을 포함해서, 프론트가 그대로 표로 그릴 수 있게). 검색 결과와 같은 `InvoiceOut` 스키마를 리스트로 반환.

### `POST /reports/material-ledger/entries/{invoice_id}/exclude` (신규 엔드포인트)

해당 송장의 `included_in_ledger`를 `False`로 바꾼다. 송장 자체는 삭제하지 않는다. 존재하지 않으면 404, 애초에 포함되어 있지 않았으면(이미 False) 그대로 성공 처리(멱등).

## 프론트엔드 변경

### `LedgerPage.jsx`

- 기존 폼(검수자/담당감리원 입력 + 생성 버튼)은 그대로 유지
- 생성 버튼 아래에 **"현재 수불부 포함 목록"** 표를 추가:
  - 페이지 진입 시 `GET /reports/material-ledger/entries` 호출해서 표시 (연번/반입일/규격/반입량 컬럼)
  - 각 행에 "제외" 버튼 → 확인창 → `POST .../exclude` 호출 → 성공하면 목록에서 제거
  - 목록이 비어있으면 "아직 수불부에 포함된 기록이 없습니다" 안내
- "수불부 생성" 성공 후에는 목록을 다시 불러와 새로 포함된 항목이 반영되게 한다
- 경고 배너에 "이미 포함된 N건은 건너뛰었습니다" 같은 메시지가 오면 그대로 표시(기존 경고 배너 재사용)

### `api.js`

- `getLedgerEntries()`: `GET /reports/material-ledger/entries`
- `excludeLedgerEntry(invoiceId)`: `POST /reports/material-ledger/entries/{invoiceId}/exclude`

## 에러 처리

- 신규로 추가할 것도 없고 기존 포함 목록도 비어있으면 400 ("수불부에 포함할 철근 자재 기록이 없습니다")
- `exclude` 대상 송장이 존재하지 않으면 404
- 그 외 기존 원칙(공유 비밀번호 인증 등) 동일하게 유지

## 테스트 전략

- `crud.py`에 추가되는 `include_invoices_in_ledger(db, invoice_ids)` / `list_ledger_invoices(db)` / `exclude_invoice_from_ledger(db, invoice_id)` 단위 테스트: 플래그가 정확히 켜지는지, 이미 켜진 건 중복으로 다시 켜져도 문제없는지, 목록 조회가 반입일 순인지, 제외 후 목록 조회 시 빠지는지
- `/reports/material-ledger` 통합 테스트 갱신: 1차 생성(2건) → 검증 → 2차 생성(새 1건 선택, 기존 2건 중 1건을 다시 선택) → 결과 파일에 총 3건이 반입일 순으로 들어있는지, "이미 포함된 1건은 건너뛰었습니다" 경고가 오는지
- `/reports/material-ledger/entries`, `/reports/material-ledger/entries/{id}/exclude` 엔드포인트 테스트: 목록 조회, 제외 후 목록에서 사라짐, 제외해도 송장 자체는 `GET /invoices/{id}`로 계속 조회되는지, 존재하지 않는 id 제외 시 404
- 프론트: 로컬 브라우저로 1차 생성 → 목록 표시 확인 → 하나 제외 → 목록에서 사라짐 확인 → 2차 생성 시 파일에서 빠져있는지까지 수동 검증

## 범위 밖

- 여러 개의 독립된 수불부(예: 프로젝트별/연도별로 분리 관리)를 만드는 기능 — 지금은 전체 앱에 걸쳐 하나의 누적 수불부만 존재한다
- 커플러 수불부의 동일 기능 — 기존 설계 문서와 마찬가지로 철근 시트만 대상
- 포함 목록의 순서를 사용자가 수동으로 재정렬하는 기능 — 항상 반입일 순으로 자동 정렬
