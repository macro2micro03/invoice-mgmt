# 반입송장 → 자재검수요청서 자동 생성 (엑셀 서식 방식) — 설계 문서

## 배경

`2026-07-07-material-inspection-report-design.md`에서 python-docx로 워드 문서를 새로 그려서 생성하는 방식을 구현했으나, 실제 현장에서 쓰는 정식 엑셀 서식(`(Form)자재검수요청서.xlsx`)을 그대로 활용해 특정 셀만 채우는 방식으로 전환하기로 했다. **이 문서는 이전 설계를 대체한다** — 워드 생성 기능(`report_docx.py`)은 제거하고 엑셀 템플릿 채우기로 완전히 바꾼다.

데이터 추출/합산 로직(`report_parser.py`: 갑지 탐지, 규격별 합산, 거래처 인식)은 그대로 재사용한다. 바뀌는 것은 "합산된 데이터를 어떤 산출물에 어떻게 채우는가"뿐이다.

## 템플릿 구조 (실제 파일 검증됨)

`(Form)자재검수요청서.xlsx`는 단일 시트, 86행 x 10열 구조로, 1페이지(자재검수요청서)~3페이지(철강 자재 점검표)+사진대지가 한 시트 안에 이어져 있다. 이 템플릿 파일을 `backend/app/templates/material_inspection_form.xlsx`로 저장소에 포함하고, 매 요청마다 이 파일을 열어(원본은 불변) 특정 셀만 값을 넣은 사본을 반환한다.

### 자동 채움 셀

| 필드 | 셀 | 값 | 비고 |
|---|---|---|---|
| 공사명 | `B2` | `project_name` | |
| 공종명 | `B3` (텍스트 치환) | 선택된 항목의 `□`를 `■`로 치환 | 예: `"건축 □ 토목 □ ..."` → `"건축 ■ 토목 □ ..."` |
| 문서번호 | `B4` | `"건축(자검)-{material_type}-{N}호"` | 기존 `crud.get_next_report_number` 재사용 |
| 접수일자 | `G4` | 오늘 날짜 | |
| 검수일자(1p) | `G5` | 오늘 날짜 | |
| 자재 내역 표 | `A9:J24` (규격 수만큼 행 사용, 최대 16행) | 품명(`material_type`)/규격(`spec`)/단위(`"Ton"`)/수량(`quantity_ton`)/거래처(`vendor`) | A=품명, B:C=규격, D=단위, E=수량, F:G=거래처. `H`(적합)/`I`(부적합)/`J`(검수자)는 비워둠 |
| 검수요청일 | `C27` | 오늘 날짜 | |
| 통보일자 | `H27` | 오늘 날짜 | |
| 현장대리인 서명 | `C28` | `f" {sender}    (인)"` | |
| 총괄관리원 서명 | `H28` | `f" {receiver}    (인)"` | |
| 반입일자 | `H35` | 갑지들의 도착일 중 최댓값 | 새로 추출 필요 (아래 참고) |
| 검수일자(2p) | `H36` | 오늘 날짜 | |
| 납품회사 | `H37` | 거래처 | |
| 반입량 | `H38` | 합계 Ton (예: `"68.902 Ton"`) | |
| 자재규격 | `C39` | `"{material_type} {첫 규격} 외 {나머지 개수}"` (예: `"철근 SHD10 외 4"`) | 규격이 1개면 "외 N" 생략 |
| 사진대지 날짜 | `H83`, `H86` | 반입일자와 동일 값 | |

### 공란으로 유지 (사람이 직접 기입/체크)

- `G3` 승인구분 체크박스
- 자재 내역 표의 `H`(검수결과-적합)/`I`(검수결과-부적합)/`J`(검수자) 열
- `D30`~`D32` 미승인사유/처리방안 (체크박스 텍스트는 그대로 두되 체크 표시는 안 함)
- 2페이지 개별 체크리스트 결과 (43~55행, 템플릿에 이미 공란)
- 3페이지 철강 자재 점검표 판정 결과 (`G63:G79`) — **템플릿에 이미 예시값이 채워져 있으므로, 생성 시 이 범위를 명시적으로 공란 처리**
- 58행 시공담당자/담당감리자 서명란 — 건드리지 않음(템플릿 값 그대로)
- 사진대지 공종명/위치/내용(`C82`,`H82`,`C83`,`C85`,`H85`,`C86`) — 템플릿 기본값 유지

## 사진대지 사진 삽입

`사진대지` 섹션은 상단 블록(81행, 병합 `A81:J81`, 실측 약 658×378px)과 하단 블록(84행, 병합 `A84:J84`, 동일 크기)으로 구성된, 실제 사진이 들어갈 빈 공간이다. 프론트엔드에 **송장 갑지 업로드와는 별도로** 사진대지용 업로드 입력 2개를 추가한다: "사진대지 상단 사진"(여러 장 가능), "사진대지 하단 사진"(여러 장 가능).

**배치 규칙 (블록별로 동일하게 적용):**
- 사진 수 `N`에 대해 `cols = ceil(sqrt(N))`, `rows = ceil(N / cols)`로 격자를 정한다.
  - `N=1` → 1×1 (블록 전체 크기에 맞춰 배치)
  - `N=2` → 2×1 (가로로 나열)
  - `N=3~4` → 2×2 격자
  - `N=5~6` → 3×2 격자 (이하 동일한 규칙으로 일반화)
- 각 격자 칸의 크기 = `(블록 너비 / cols, 블록 높이 / rows)`.
- 각 사진은 Pillow로 원본 비율을 유지한 채 격자 칸 크기 안에 맞도록 축소(원본이 더 작으면 확대하지 않음)하고, 칸의 좌측 상단을 기준으로 배치한다.
- openpyxl의 `openpyxl.drawing.image.Image`를 이용해 계산된 픽셀 크기와 오프셋(EMU 단위, `1px = 9525 EMU`)으로 상단 블록은 81행, 하단 블록은 84행 시작 위치를 기준으로 배치한다.
- 한 블록에 사진이 없으면(업로드 안 함) 그 블록은 비워둔다 (에러 아님).

**출력 필드 추가**: `POST /reports/material-inspection`에 멀티파트 필드 `top_photos`(여러 파일), `bottom_photos`(여러 파일)를 추가한다. 둘 다 선택 사항(사진대지 없이도 보고서 생성 가능).

## 반입일자 추출 (신규)

지금까지의 `report_parser.py`는 갑지의 규격별 표와 회사명만 추출했다. "반입일자"를 채우려면 갑지 상단의 정보표(송장번호/현장명/도착일/차량번호 등)에서 **도착일**을 추가로 추출해야 한다.

- 정보표는 갑지의 `category == "table"` 요소 중, 규격별 표(`"직경"` 헤더)가 아닌 다른 표에서 찾는다.
- 각 행의 첫 셀이 "도"로 시작하고 나머지 셀에 "착 일"이 포함된 행(글자 간 공백 분리 대응, 실제 응답에서 `"도"`/`"착 일"`로 셀이 쪼개져 있음을 이미 확인함)에서 날짜 패턴(`YYYY-MM-DD`)을 정규식으로 추출한다.
- 한 줄에 날짜가 두 번 나올 수 있음(`"2026-03-31 / 2026-03-31"`, 접수일/도착일 등 중복 표기) — 첫 번째 날짜를 사용한다.
- 여러 갑지에서 각각 도착일을 추출해 **가장 늦은(최댓값) 날짜**를 최종 반입일자로 사용한다.
- 날짜를 하나도 못 찾으면(형식이 다르거나 인식 실패) 반입일자는 빈 문자열로 두고, 이 경우도 기존 경고 메커니즘(`X-Report-Warnings`)에 추가한다.

`build_report_data`의 반환값에 `"delivery_date": str`(YYYY-MM-DD 형식 또는 빈 문자열)을 추가한다.

## 아키텍처 변경

```
[프론트: 보고서 생성 화면] (기존과 동일한 입력 필드 + 파일 업로드)
      |
      v  POST /reports/material-inspection
[백엔드]
  1. (기존) 파일별 Upstage 호출 → report_parser.build_report_data (delivery_date 추가됨)
  2. (신규) report_excel.fill_material_inspection_form(template_path, **data) -> bytes
     - openpyxl로 템플릿 로드
     - 위 매핑표대로 셀 값 설정 (G63:G79는 명시적으로 빈 문자열로 초기화)
     - BytesIO에 저장해 바이트로 반환
      |
      v  응답: .xlsx 파일 다운로드 (media type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet)
```

`report_docx.py`와 그 테스트(`test_report_docx.py`)는 삭제한다. `routers/reports.py`는 `report_docx` 대신 `report_excel`을 사용하도록 교체한다. 프론트엔드 다운로드 파일명 확장자를 `.xlsx`로, `Content-Type`/`Content-Disposition`도 엑셀 MIME 타입으로 바꾼다.

## 에러 처리

- 자재 내역 표에 넣을 규격이 16개를 초과하면(템플릿이 9~24행, 16줄만 지원) `skipped_specs`로 표시하고 경고에 포함한다 (전부 버리지 않고, 넘치는 항목만 제외 — 흔치 않은 경우이므로 최대한 데이터 손실을 줄인다).
- 반입일자를 하나도 못 찾으면 경고에 포함하고 빈 문자열로 채운다.
- 그 외 에러 처리 원칙(갑지 미발견 시 400, Upstage 호출 실패 시 502)은 기존과 동일하게 유지한다.

## 테스트 전략

- `report_parser.py`의 반입일자 추출 로직에 대한 단위 테스트 추가 (여러 갑지 중 최댓값 선택, 형식이 다른 경우 등).
- `report_excel.py`에 대한 단위 테스트: 템플릿을 채운 결과를 다시 openpyxl로 열어 각 셀 값이 매핑표대로 정확히 들어갔는지, 그리고 G63:G79가 실제로 비어있는지 확인.
- `routers/reports.py` 통합 테스트: 응답이 유효한 `.xlsx`(로 로드 가능)인지, `Content-Type`이 엑셀 MIME인지 확인.
- 사진 격자 배치 계산 로직(`cols`/`rows`/칸 크기 산출)에 대한 단위 테스트 (N=1,2,3,4,5,6 각각 기대하는 격자 크기 확인). 실제 이미지 삽입 자체는 생성된 파일에 이미지가 N장 들어있는지(`ws._images` 개수)로 검증.
- 실제 첨부된 원본 21페이지 PDF로 로컬 수동 검증 (이미 이전 라운드에서 규격별 합산은 검증됨 — 반입일자/자재규격 요약 문자열 등 새로 추가된 필드도 실제 값과 맞는지 확인).

## 범위 밖

- 3페이지 철강 자재 점검표, 2페이지 개별 체크리스트 항목의 자동 판정
- 58행 시공담당자/담당감리자 서명
- 다른 회사/다른 레이아웃의 서식 지원 (이 템플릿 구조에 특화됨)
- 사진대지 블록 하나에 격자가 다 못 채울 만큼 사진이 매우 많은 경우(예: 수십 장)의 별도 페이지/시트 분리 — 이번 범위에서는 격자를 계속 촘촘하게 줄여서라도 한 블록 안에 다 배치한다
